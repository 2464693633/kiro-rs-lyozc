# 在管理界面查看检测请求

管理后台现已内置内容观察，不需要再部署 mitmproxy。

1. 在「客户端 Key」创建一把用于检测的专用 Key。
2. 打开「请求日志 → 内容观察」，选择该 Key，打开「观察中」开关。
3. 在 CCTest 或其他客户端中使用同一把 Key 请求本服务。
4. 观察列表每 5 秒刷新。展开一行即可切换「原始请求」与「响应 / SSE」，并复制或导出。
5. 测试完成后关闭观察。已保存的记录在保留期内仍可查看。

## 能看到什么

- 协议转换前的请求正文，包括尚未被 Rust 请求类型支持的字段。
- 结构化输出、工具选择、搜索、文档、图片、thinking、签名回传与缓存控制等结构特征。
- 数字指纹、模型身份、知识截止时间等用词匹配会标记为「推测」，不能据此证明来源是某个网站。
- 最终发往客户端的响应正文，包括 SSE、状态码、耗时以及完整结束或中断状态。
- 等待响应头期间被取消、流中途断开、上游返回 HTTP 错误也会保留相应观察记录。

响应正文在发送结束或断开后保存。观察界面不需要先收完整个回答才允许 API 客户端收到内容。

## 保存范围

默认关闭，只捕获已经鉴权且命中所选专用客户端 Key 的 API 请求。系统默认 Key 不在开启选择范围。记录不包含 Authorization、x-api-key、Cookie 等请求头，也不保存 URL 查询参数。

原始提示词、图片和文档内容属于请求正文，会随此次主动开启的观察保存。每侧正文最多保存 256 KiB，超限明确显示「仅保存前缀」；转发的真实内容不会因保存上限被截断。超过 8 MiB 的请求不执行特征解析，只保留正文前缀和长度信息。

记录保存于 `traces.db` 的独立观察表，保留 24 小时、最多 500 条。列表只读取摘要，展开时才读取正文。观察开关与选中 Key 也保存在该数据库，重启后保留设置；重启前未完成的记录显示中断。该设置独立于普通链路追踪开关。

## 管理 API

这些接口沿用管理后台鉴权：

```text
GET /api/admin/config/request-observation
PUT /api/admin/config/request-observation
GET /api/admin/observations?keyId=1&limit=25&offset=0
GET /api/admin/observations/{id}
```

配置请求体示例：

```json
{ "enabled": true, "keyId": 1 }
```

更改配置不会改写模型请求、响应、签名或 Token 用量。要核对 CCTest 某项测试的准确内容，应依据你实际发起检测的时间和专用 Key，读取这轮真实收到的请求。

外部反向代理抓包仍可使用 `tools/request-observer`，但它是独立方案，文件捕获不会自动导入本管理界面。
