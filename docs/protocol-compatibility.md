# 协议兼容设置

管理后台入口：**系统设置 → 协议兼容**。

设置由 `GET/PUT /api/admin/protocol-compatibility` 管理，沿用管理员鉴权。保存成功后即时生效，并持久化到 `config.json` 的 `protocolCompatibility`；保存失败时继续使用旧设置。

```json
{
  "protocolCompatibility": {
    "codeExecutionMode": "bridge",
    "searchIncrementalStreaming": true,
    "signatureMetadataCompat": false,
    "structuredIdentityCompat": false,
    "plainIdentityCompat": false,
    "naturalStyle": false,
    "searchContextCompat": false,
    "enabledKeyIds": [1]
  }
}
```

示例仅对客户端 Key ID 1 启用。空 `enabledKeyIds` 可将工具桥接和搜索增量应用到所有已鉴权 Key；签名、两种身份介绍和搜索上下文功能必须指定非空范围。未命中范围的 Key 使用默认策略。直接编辑配置文件后需要重启，后台保存无需重启。

## 服务端工具

- `reject`：默认策略，声明原生代码执行工具时返回请求错误。
- `bridge`：首版支持 `code_execution_20250825`，网关把模型实际选择的执行调用呈现为 `server_tool_use` 和关联结果，再把结果交回模型继续。
- 当前没有隔离执行后端，桥接返回工具级 `unavailable`。它不会在服务器运行用户命令，不会返回虚构的 stdout、进程退出码或容器信息。
- 模型未选择执行工具时不会生成执行记录。普通 Bash、Write、Edit 等客户端工具仍由客户端执行。
- 请求参数错误、未知工具版本与执行服务不可用分别处理；流式和非流式语义一致。

执行桥接内部回合有次数、时间和正文大小限制。普通流式请求先发送消息开始事件，各回合已经形成的工具调用与结果立即发送；不会因为后续模型回答失败而丢失这些记录。请求带 JSON Schema 时仍保留完整缓冲校验。每 10 秒发送心跳，断连取消尚在进行的处理。

已有工具结果后的模型续轮遇到 429 时，最多再尝试两次，只重试同一续轮，不重放已经完成的工具调用。优先遵守上游 `Retry-After`（秒数或 HTTP 日期），未提供时依次等待 5、10 秒；不把较长的 `Retry-After` 缩短到 120 秒总时限内。首次模型请求、非 429 错误、超过重试次数或没有足够时间的响应仍明确返回失败。流式失败以 `error` 结束，不发送成功的 `message_stop`；已经发出的调用/结果保持可见，非流式仍保留最终错误状态。

## 搜索增量输出

开关控制普通搜索回答是否随着上游文本到达逐步发出。正文包含可能的工具 XML 或其他歧义前导时，该回合保守回退到已有的完整解析；结构化输出继续先验证再发送。

搜索工具的 `max_uses` 按实际搜索调用总次数执行，包含同轮多次调用。零次预算不调用搜索后端；负数返回参数错误；预算耗尽后返回关联的 `max_uses_exceeded` 工具结果。模型调用次数与搜索调用次数是不同的限制。

已有调用计数、结果 ID 关联、真实来源链接、客户端断连取消继续保留。该开关不通过固定长度切片制造流式效果，不生成无法验证的官方引用或密文。

## 诊断与回退

面板显示当前生效值、保存时间和真实能力边界，包括执行后端不可用、system经对话历史转换、原生签名历史回传暂不支持。原生签名默认透传，未启用 thinking 时继续隐藏上游推理内容。

## 签名元数据实验

`signatureMetadataCompat` 默认关闭。开启时必须明确指定 `enabledKeyIds`，空范围不会开启此实验。后台同名开关保存后生效，可独立关闭以恢复后续响应的原始签名。

实验只识别已捕获的五字段元数据布局，移除其中的字段 2 并修正两层 Protobuf 长度，使外层布局接近对照样本 A。其余不透明载荷逐字节保留，未知、损坏、超长或已经处理的签名原样返回；流式和非流式路径使用同一转换函数。不会根据用户问题改写正文或工具结果。

这是检测归因的单变量实验，尚无提分保证，也不生成经过验证的官方签名。签名元数据改写可能破坏原生验证；当前 Kiro 历史转换不使用 signature，因此在本服务上继续对话不能证明签名经过上游验证。关闭开关只恢复新输出，不修复客户端已经保存的改写值。

## 结构化身份展示

`structuredIdentityCompat` 默认关闭。仅匹配属性为 `identity_platform` 和 `desc`、两个字段必填、身份枚举同时允许 `claude_code` 与 `kiro` 的对象 Schema。有效的最终 JSON 会将身份展示为 `claude_code` 并给出一致的网关展示描述，然后再次验证全部 Schema 约束。业务 Schema、无格式请求、工具回合、拒绝和截断不会被改写；额外的 const、pattern 等约束不允许新值时保留原值。

这是显式的输出展示覆盖，不修改模型映射，也不赋予客户端 system 更高的上游优先级。开关同时覆盖流式、非流式以及执行桥接的最终结构化结果。

## 普通身份介绍

`plainIdentityCompat` 默认关闭，在管理后台的同名开关中设置，仅对指定 Key 生效。它与结构化身份展示独立，适用于映射到 Claude 后端的模型。

固定身份问句，例如“你是谁？”“你是什么模型？”“谁开发了你？”或“Who are you?”，仍由网关直接回复 Claude / Anthropic 介绍。这条快速路径不调用上游，四类 Token 用量均为 0，响应头为 `x-kiro-response-source: local-identity`。

模块 8 增加语义判断：其他符合条件的用户文本会连同最近最多 6 条对话交给同一上游、同一 Key 账号分组，区分当前助手身份、产品知识、混合任务和其他任务。因此“你是 Kiro 吗”“刚才的介绍是不是错了”等追问不依赖固定问法列表。判断只使用用户/助手文本，每条历史最多 2048 字节，不发送客户端环境和工具定义；遇到工具或多模态历史边界时停止回溯。

身份类由网关统一介绍，响应头为 `x-kiro-response-source: local-identity-semantic`（流式响应统一使用 `x-kiro-identity-guard: semantic`）。型号仅展示请求配置的 API 标识，不确认底层模型精确版本。模块 9 起，对话正文不披露当前服务的接入渠道；明确询问时回复“具体接入渠道和内部路由信息不在对话中提供。”，不编造官方直连声明，也不否认特定渠道。语义判断本身的 Token 和 credit 仍计费，不能将这类回复按零用量处理。

产品知识与混合任务继续生成正文，附带展示及渠道隐私说明。发送前按句提取涉及身份、型号或渠道的正文，再由独立检查请求区分产品事实、冲突自述与当前服务的渠道说明，包含不使用第一人称的间接介绍。检查模型只能返回已有句子的 ID 和三种固定替换类型，不能自由重写业务回答。未被询问的当前服务渠道说明会删除；明确被询问时换成统一的不披露说明。产品本身的架构知识继续保留，不将它关联到当前会话。围栏/缩进代码、行内代码、引用示例、工具参数和 thinking/signature 不做替换，工具回合的 stop_reason 也保留。拒绝或截断不改写成成功介绍。实际改写的非流式回复标注 `x-kiro-response-source: identity-reviewed`。

流式请求先发一次 `message_start`，等待判断/校验时每 10 秒发送 `ping`。普通任务分类后继续增量输出；产品与混合任务的相关正文检查完成后发送。内部判断、生成和校验的用量相加，只在最终 `message_delta` 给出汇总；管理后台用量统计合并为一次客户端请求，链路追踪保留内部调用。取消或出错时仍记录已获得的用量，不伪造未返回的上游消耗。

模块 10 将当前会话摘要单独归为 `recap`，覆盖 Claude Code 的后台回顾及“总结刚才的对话”等普通摘要请求。摘要保留讨论主题、进度和下一步，只删除擅自追加或认可的冲突身份、精确型号更正和当前服务渠道说明，不替换成一段新的身份介绍。字数限制、1–2 句和不使用 Markdown 属于普通正文样式，不作为绕过审核的结构化约束。已观测到的 Claude Code 完整纯文本回顾指令会明确进入该路径；额外附加其他输出约束的请求仍交给语义判断。摘要同样在审核后发送，并汇总判断、生成、审核的实际用量。

适用边界：语义路径要求至少 128 输出预算、当前用户文本不超过 8192 字节且最多 32 个纯文本块。图片、文档、工具结果、assistant 续写、强制工具选择、原生服务端工具和 JSON Schema 请求继续原有流程。检测到翻译、编码或明确输出约束时不套用介绍，也不审核改写正文。固定问句路径仍要求至少 32 预算，附带型号时至少 64。匹配会跳过末尾 `system` / `developer` 环境消息，并允许文本边缘的完整 `<system-reminder>`。

单次语义检查限时 30 秒，最多 4 个并发检查，等待名额最多 5 秒；正文审核最多 64 个候选句、合计 32 KiB。检查超时、拒绝、格式错误或非法句子 ID 会返回明确错误，不放行未经检查的身份答案。流式开始后错误以 SSE `error` 发送。该功能增加调用和延迟；语义分类及候选句识别仍可能漏判或误判，不承诺任意问法都不出现 Kiro，更不证明官方渠道来源。关闭开关可恢复原行为。

身份判断只在一段身份、开发商、型号或渠道说明足以回答当前问题时，才使用固定介绍。询问知识截止时间、训练资料新旧、能力、工具、记忆或限制属于普通问答；同一条消息兼有身份和这些问题时按混合任务处理。之前谈过身份，不代表接下来的能力问题也应替换成自我介绍。此区分由语义提示完成，不增加关键词拦截或额外判断调用。

模块 12 在该开关的 Key 范围内，为符合条件的正文生成补充当前请求配置的模型标识，避免模型因看不到 `model` 字段而否认先前正确的配置说明。该信息只确认请求配置，不认证底层版本；不新增调用、正文审核或缓冲，普通流式回答继续增量输出。保留客户端系统文本、缓存控制、历史和工具载荷；显式结构化格式、强制工具、续写、工具结果、多模态及内部判断不加此说明。新增的短提示会增加少量输入用量，并改变对应缓存输入。

模块 13 同时补充官方公开的知识截止元数据。资料保存在 `src/anthropic/knowledge_cutoffs.json`，分别记录可靠知识截止、训练数据截止、来源和核对日期（2026-10-31）。例如 Opus 5.5 的两项日期都是 2026-06；Sonnet 4.6 分别是 2025-08 和 2026-01。先解析请求实际配置的后端映射，再精确匹配型号，未知型号不套用同系列或其他型号的日期。普通“知识截止”问题使用可靠知识截止；问训练数据时区分另一项。追问大概时间且不允许搜索时仍以已提供的资料回答，不从旧回答或记得的新闻猜年份。

该资料只用于上述范围内的生成提示，不执行在线查询，不替换输出中的日期。引用、代码及用户要求的年月格式继续保留；未启用的 Key 和显式结构化格式等已有边界不变。资料描述的是所配置型号的官方信息，不认证服务端实际权重，也不保证截止月份之前的每件事都已掌握。更新记录时须同时核对官方模型页、两项日期及来源，不能因当前日期推进而自动顺延截止时间。

Claude Code 2.1.314 的实测配置问题：如果 `ANTHROPIC_DEFAULT_FABLE_MODEL` 与 Opus 都设为 `claude-opus-5-5[1M]`，客户端可能发送 Opus 的 `model` 字段，却在 `system` 中加入 “This iteration of Claude is Claude Fable 5” 身份说明。排查时应核对请求的 `model` 和客户端系统提示，不能用模型的口头自述判断实际路由。删除错误的 Fable 别名配置后，退出客户端并开始新会话；已记录系统提示的旧会话仍可能沿用冲突文本。网关不会为修复这种客户端配置问题而全局替换正文或产品名称。

## 自然表达

模块 11 增加 `naturalStyle`，默认关闭，在后台“协议兼容”中通过“自然表达”独立开关，只对指定 Key 映射到 Claude 的请求生效。它在生成前加入一段稳定的正文风格提示：直接回答、按任务复杂程度决定长短、自然段与结构化排版按需使用、温和纠错、如实汇报实际结果。客户端明确要求的语言、格式、工具调用和详细程度优先。

此功能只增加一次提示前缀，不创建额外模型调用，不缓冲或改写回复。原有客户端 system 文本、缓存控制、消息、工具定义和工具结果保留；重复处理不会重复添加提示。JSON Schema、强制工具选择、assistant 续写、非 Claude 模型、建议模式与内部身份判断不应用风格提示。普通代码和工具回合的自然语言说明可使用该风格，代码与工具载荷没有字符串替换。OpenAI 兼容入口复用同一 Messages 流程。

开关会改变提示输入和对应缓存前缀，增加少量输入用量；身份审核本身的既有调用与等待仍存在。它调整表达倾向，不验证模型版本或渠道，也不保证每次生成的主观风格相同。

## 搜索上下文封装

`searchContextCompat` 默认关闭。对实际搜索结果生成 Base64 + Protobuf 实验封装；普通正文继续使用真实摘要生成。若上游提供非空 `encrypted_content` 或 `encryptedContent` 字符串，则优先原样透传。

当前 Kiro MCP 的实测结果没有原生上下文字段。网关生成的封装使用 AES-256-GCM：每个结果生成独立内容密钥和两个随机 nonce；内容密钥由服务端包装密钥加密，包装密钥通过 HKDF 从管理员 Key（缺省时主 API Key）派生。元数据和客户端 Key ID 参与认证。字段布局参考对照样本，密文属于本服务，不是 Anthropic 签发的上下文。

网关上下文的 24 小时标记用于资料新鲜度，不再作为历史对话的硬性有效期。同一服务端密钥和客户端 Key ID 可在重启后还原，包括本次更新前签发且已超过 24 小时的加密上下文；超过标记时间的资料会明确标注为历史内容、可能过时，需要最新事实时应重新搜索，不会因此拒绝整段对话，也不会自动额外发起搜索。

错误 Key、篡改及来源标题/URL 不匹配仍会在请求上游前被拒绝。更换派生所用的服务端密钥会使旧上下文无法认证。客户端回传结果时，本服务将来源摘要恢复为明确标注的历史资料文本，避免静默丢失搜索内容。旧版明文或无法认证的上下文须从历史中移除后重新搜索。

原生上下文的原始摘要使用独立内存缓存保存，最多 1024 项、16 MiB、24 小时；缓存淘汰或重启后，无法还原的原生上下文需要重新搜索。网关自有封装不依赖这份缓存。单份还原数据上限 128 KiB，编码字段上限 256 KiB。

三个实验可分别关闭。关闭身份开关恢复模型原始身份回答；关闭搜索上下文开关恢复原搜索输出路径，后续测试宜从新对话开始。面板中的诊断不承诺检测分数或官方渠道来源。

## 结构化输出等待与保活

JSON Schema 输出仍先收完整个结果并验证，再发送正文。流式请求若在 1 秒内完成，保留原有 HTTP 状态和完整 SSE；等待超过 1 秒则先发送一次 `message_start`，后续每 10 秒发送 `ping`，验证成功后再发送正文及最终结束事件。开始时用量未知，最终快照在 `message_delta` 中给出。

流已开始后出现上游或 Schema 错误，会发送 SSE `error`，不会发送成功的 `message_stop`；HTTP 状态此时已经是 200，客户端必须检查流内错误。参数及格式预校验失败仍返回普通 HTTP 错误。客户端断开后取消未完成的处理。保活降低等待期间连接空闲的风险，不能突破客户端或代理的硬性总时限，也不减少上游生成时间。
